# 153. 寻找旋转排序数组中的最小值

[LeetCode 153](https://leetcode.com/problems/find-minimum-in-rotated-sorted-array/) · 中等

相关：[[LeetCode 刷题汇总]] | [[33. 搜索旋转排序数组]]

## 题意

无重复元素的升序数组被旋转过（如 `[3,4,5,1,2]`），用 O(log n) 找出最小值。

## 思路

和 `nums[right]` 比较来判断最小值在哪一侧：

- `nums[mid] > nums[right]`：mid 落在左段（较大那段），最小值在 mid 右边 → `left = mid + 1`
- 否则：mid 落在右段，mid 本身可能就是最小值 → `right = mid`

```python
class Solution:
    def findMin(self, nums: List[int]) -> int:
        left, right = 0, len(nums) - 1

        while left < right:            # 注意不是 <=
            mid = (left + right) // 2
            if nums[mid] > nums[right]:
                left = mid + 1         # 最小值在右半边（不含 mid）
            else:
                right = mid            # mid 可能就是最小值

        return nums[left]
```

时间 O(log n)，空间 O(1)。

## 为什么和 right 比而不是 left

与 `left` 比较时无法区分下面两种情况，需要额外判断数组是否被旋转；与 `right` 比则天然二分：

```
[3,1,2]   nums[mid]=1 < nums[left]=3   → 最小值在左半
[1,2,3]   nums[mid]=2 > nums[left]=1   → 最小值就是 left
```

## 易错点

- 循环条件是 `left < right`，写成 `<=` 会因为 `right = mid` 死循环
- 收缩用 `right = mid` 而非 `mid - 1`，否则会跳过答案
- 数组可能完全没被旋转（`[1,2,3]`），本模板已覆盖，不需要特判
- 有重复元素时是 154 题，需额外处理 `nums[mid] == nums[right]`（`right -= 1`），最坏退化 O(n)

## 找边界型二分模板

```python
while left < right:
    mid = (left + right) // 2
    if 条件:  left = mid + 1     # mid 一定不是答案
    else:     right = mid        # mid 可能是答案
return nums[left]                # 退出时 left == right
```
